[8M] ★★★ Q1a: Digital Signature appeared in 5 paper(s)
What is a digital signature? Which security goals does it meet?
1. Definition (2 marks)
A digital signature is a cryptographic value computed from a message and the signer's private key. Anyone holding the signer's public key can verify it. It is the electronic equivalent of a handwritten signature, but it is bound to the message content, so a signature cannot be copied onto another document.
2. Diagram (2 marks): signing and verification 3. Working / explanation (2 marks)
  1. Key generation: Alice generates a key pair (private d, public e) and publishes e through a certificate.
  2. Hashing: Alice computes h = H(M) with SHA-256 so the signature is short and bound to the whole message.
  3. Signing: S = Sign(h, private key). For RSA: S = hd mod n.
  4. Sending: Alice sends (M, S).
  5. Verification: Bob recomputes h1 = H(M'), recovers h2 = Se mod n and compares. A mismatch means the message or signature was altered, or the signer is not Alice.
# Pseudocode (RSA-style)
sign(M, d, n):    h = SHA256(M);  return pow(h, d, n)
verify(M, S, e, n): h1 = SHA256(M); h2 = pow(S, e, n); return h1 == h2
Security goals met (explain each)
GoalHow the signature achieves it
AuthenticationOnly the holder of the private key can produce S, so verification proves the sender's identity.
IntegrityChanging even one bit of M changes H(M), so verification fails.
Non-repudiationAlice cannot later deny signing; the private key is hers alone and a third party can verify S.
ConfidentialityNot met. M travels in plaintext unless separately encrypted.
4. Example (2 marks)

Alice e-signs a ₹5 lakh purchase order for Bob. If an attacker raises the amount to ₹50 lakh in transit, Bob's recomputed hash differs from the decrypted hash and the order is rejected. Alice also cannot claim she never sent it. Real uses: Aadhaar eSign, signed software updates, TLS certificates, e-filing of GST returns.

AlgorithmBasisNote
RSA signatureFactoringWidely used, large keys (2048+ bits)
DSADiscrete logSignatures only, standard by NIST
ECDSAElliptic curvesShort keys, fast, used in Bitcoin
AdvantagesLimitations
Paperless, fast, legally valid (IT Act 2000)Needs PKI and certificate management
Detects tampering, offers non-repudiationPrivate key theft compromises everything
Works over open networksNo confidentiality; computation cost
Exam Summary: Digital Signature - What is a digital signature? Which security goals does it meet?
Memory Trick: Mnemonic: H-E-S-V = Hash, Encrypt with private, Send, Verify with public. Goals = A-I-N (Auth, Integrity, Non-repudiation).
[6M] ★★★ Q1b: Diffie-Hellman appeared in 3 paper(s)
Explain Diffie-Hellman key exchange with example.
Definition: Diffie-Hellman (1976) lets two parties establish a shared secret key over an insecure channel without ever sending the key. Its security rests on the discrete logarithm problem: given g, p and gx mod p, finding x is computationally infeasible for large p.
Steps
  1. Agree on public prime p and generator g.
  2. Alice picks secret a and sends A = ga mod p; Bob picks b and sends B = gb mod p.
  3. Alice computes Ba mod p and Bob computes Ab mod p; both equal gab mod p.
Example 
p = 23, g = 5, a = 6, b = 15
A = 5^6  mod 23 = 8          B = 5^15 mod 23 = 19
Alice: K = 19^6  mod 23 = 2
Bob  : K =  8^15 mod 23 = 2   ✓ same key
Man-in-the-middle attack (frequently asked)

DH has no authentication. Mallory intercepts A and B, runs DH separately with Alice (key K1) and Bob (key K2) and relays traffic while reading it. Fix: authenticate the exchanged values with digital signatures or certificates (as in TLS, IKE).

AdvantagesLimitations
No key transmitted; forward secrecy with ephemeral keysNo authentication, so MITM is possible
Simple; used in TLS, IPSec (IKE), SSHComputation heavy; weak parameters risk (Logjam)
Exam Summary: Diffie-Hellman - Explain Diffie-Hellman key exchange with example.
Memory Trick: Trick: 'Mix paint' - swap mixed colours, add your own secret: K = g^ab. Needs authentication to stop MITM.

Find X: X=1(mod 5), 6(mod 7), 8(mod 11).
Definition: If m1, m2, … mk are pairwise coprime, the system X ≡ ai (mod mi) has a unique solution modulo M = m1·m2·…·mk, given by X = Σ ai·Mi·(Mi-1 mod mi) mod M, where Mi = M/mi.
iaᵢmᵢMᵢ = 385/mᵢMᵢ⁻¹ mod mᵢaᵢ·Mᵢ·inv
115773 (77≡2, 2·3=6≡1)231
267556 (55≡6, 6·6=36≡1)1980
3811356 (35≡2, 2·6=12≡1)1680
M = 5·7·11 = 385
X = (231 + 1980 + 1680) mod 385 = 3891 mod 385 = 41
Check: 41 mod 5 = 1 ✓   41 mod 7 = 6 ✓   41 mod 11 = 8 ✓

Applications: speeding up RSA decryption (compute mod p and mod q separately), secret sharing, residue number systems.

[8M] ★★★ Q2a: SHA-1 appeared in 3 paper(s)
Explain SHA-1 with diagram.

SHA-1 produces a 160-bit digest from messages under 2⁶⁴ bits, using 512-bit blocks and 80 rounds.

for t in 0..79:
  TEMP = ROTL5(A) + f(t,B,C,D) + E + Wt + Kt
  E=D; D=C; C=ROTL30(B); B=A; A=TEMP
H0..H4 += A..E     # per block

Steps: (1) padding, (2) append length, (3) init 5 buffers, (4) process each block (W expanded 16→80 words), (5) output H0‖H1‖H2‖H3‖H4. Example: SHA-1("abc") = a9993e36…d89d.

Exam Summary: SHA-1 - Explain SHA-1 with diagram.
Memory Trick: SHA-1: 512-bit block, 80 rounds, 160-bit output, 5 registers A-E. '5-8-16' = 5 regs, 80 rounds, 160 bits.

[7M] ★★ Q8a: SQL Injection appeared in 2 paper(s)
What is SQL injection? Explain in detail.

Injecting SQL through input that is concatenated into a query.

query = "SELECT * FROM users WHERE name='" + u + "' AND pass='" + p + "'"
input u = admin' --   →  ... WHERE name='admin' --' AND ...  (password check bypassed)
Also: ' OR '1'='1  |  UNION SELECT ...  |  '; DROP TABLE users;--

Types: in-band, blind, error-based. Prevention: prepared statements, input validation, least privilege, WAF.

cursor.execute("SELECT * FROM users WHERE name=%s", (u,))  # safe

Q1a: Wireless Sensor Network (WSN) Architecture ★★★ 5/5 Papers [6M]

📌 Definition

A Wireless Sensor Network (WSN) is a collection of spatially distributed autonomous sensor nodes that cooperatively monitor physical or environmental conditions (temperature, sound, pressure, motion) and communicate the collected data wirelessly to a central base station or sink node.

🏗️ Architecture Diagram

🔧 Key Components of WSN

ComponentDescriptionRole
Sensor NodeTiny device with sensor, MCU, radio, powerSenses and transmits data
GatewayCluster head or aggregator nodeCollects data from multiple nodes
Base Station / SinkHigh-power node connected to internetReceives all data, communicates with server
Cloud/ServerRemote data storage and processingAnalysis, visualization, alerts

📱 Sensor Node Internal Architecture

✅ Key Features of WSN

  • Self-organizing: Nodes automatically form a network without manual configuration
  • Scalability: New nodes can be added easily
  • Fault tolerance: Network continues even if some nodes fail
  • Energy efficiency: Low power protocols to maximize battery life
  • Multi-hop communication: Data is relayed through intermediate nodes
  • Ad-hoc deployment: Can be deployed in hostile/inaccessible environments

⚠️ Design Challenges

  • Energy constraints: Limited battery life; nodes must conserve energy
  • Limited bandwidth: Low data rate wireless channels
  • Security: Vulnerable to eavesdropping and attacks in open wireless medium
  • Data aggregation: Reducing redundant data before transmission
  • Routing: Finding energy-efficient paths in dynamic network topology
  • QoS: Maintaining reliability and latency in lossy networks

Q1b: WSN for Healthcare Monitoring ★★ 3/5 Papers [6M]

📌 Introduction

WSN enables remote health monitoring by using body-worn or implanted sensor nodes that continuously collect patient vitals and transmit them wirelessly to healthcare providers.

🏥 Healthcare WSN Architecture Diagram

⚙️ Working Process

  1. Body-worn sensors (heart rate, SpO2, temperature) collect vital signs continuously
  2. Sensor nodes transmit data to personal gateway (smartphone) via Bluetooth/ZigBee
  3. Gateway aggregates data and sends to hospital server over WiFi/4G/Internet
  4. Cloud server stores Electronic Health Records (EHR) and runs AI algorithms
  5. Doctors access dashboards; automated alerts sent if vitals cross thresholds

✅ Advantages

  • Continuous remote monitoring without hospital admission
  • Early detection of abnormalities → reduced mortality
  • Cost-effective: reduces hospital visits
  • Useful for elderly, chronic disease patients

📌 IaaS — Infrastructure as a Service

Definition: IaaS provides fundamental computing resources (VMs, storage, networking) on-demand over the internet on a pay-per-use basis.

Advantages: Complete control over infrastructure; no hardware investment; pay as you go; easy scaling; disaster recovery.

📌 PaaS — Platform as a Service

Definition: PaaS provides a platform allowing customers to develop, run, and manage applications without maintaining the underlying infrastructure.

Advantages: Faster app development; no server management; built-in scalability; collaboration tools; reduced time to market.

📌 SaaS — Software as a Service

Definition: SaaS delivers software applications over the internet, on-demand, typically on a subscription basis.

Advantages: No installation needed; accessible from anywhere; automatic updates; cost-effective; multi-user access.

Q3a: PIR Sensor Interfacing with Arduino UNO ★★★ 4/5 Papers [8M]

📌 What is a PIR Sensor?

A PIR (Passive Infrared) sensor detects motion by measuring changes in infrared radiation emitted by warm bodies (humans, animals). It is "passive" because it does not emit any radiation itself; it only detects changes in ambient infrared energy.

⚙️ Working Principle

  • Contains two pyroelectric sensors connected in opposition
  • When no motion: both sensors detect same IR level → output = LOW
  • When motion detected: one sensor receives more IR than other → differential → output = HIGH
  • Output pin goes HIGH for 1–10 seconds (adjustable via potentiometer)

🔌 Interfacing Diagram: PIR Sensor with Arduino UNO

💻 Arduino Program — PIR Motion Detection with Buzzer

// PIR Sensor Motion Detection with Buzzer
// PIR OUT → D2, Buzzer → D7

int pirPin = 2;   // PIR sensor output pin
int buzzerPin = 7; // Buzzer pin
int pirState = 0; // Variable to store PIR state

void setup() {
  pinMode(pirPin, INPUT);     // PIR as input
  pinMode(buzzerPin, OUTPUT); // Buzzer as output
  Serial.begin(9600);          // Initialize serial monitor
  Serial.println("PIR Sensor Ready...");
}

void loop() {
  pirState = digitalRead(pirPin); // Read PIR output

  if (pirState == HIGH) {        // Motion detected
    digitalWrite(buzzerPin, HIGH); // Turn ON buzzer
    Serial.println("Motion Detected! Buzzer ON");
    delay(2000);                   // Keep buzzer on 2 seconds
  } else {                         // No motion
    digitalWrite(buzzerPin, LOW);  // Turn OFF buzzer
    Serial.println("No Motion. Buzzer OFF");
  }
  delay(100); // Small debounce delay
}

🌡️ LM35 Temperature Sensor

LM35 is an analog temperature sensor that outputs 10mV per °C (at 0°C it gives 0V, at 25°C it gives 250mV). It directly gives readings in Celsius without conversion.

Formula: Temperature (°C) = (ADC_Value × 5000mV / 1024) / 10

💻 Arduino Program — LM35 Temperature on Serial Monitor

// LM35 Temperature Sensor with Arduino UNO
// LM35 Vout → A0, VCC → 5V, GND → GND

int sensorPin = A0; // Analog pin for LM35
int sensorValue;
float temperature;

void setup() {
  Serial.begin(9600);
  Serial.println("LM35 Temperature Sensor");
  Serial.println("========================");
}

void loop() {
  sensorValue = analogRead(sensorPin);     // Read ADC value (0-1023)
  
  // Convert ADC value to millivolts
  // 10mV per degree Celsius, 5V ref = 5000mV
  temperature = (sensorValue * 5000.0 / 1024.0) / 10.0;
  
  Serial.print("Temperature: ");
  Serial.print(temperature);
  Serial.println(" °C");
  
  delay(1000); // Read every 1 second
}

Pin 1 (VS / VCC) → 5V | Pin 2 (Vout) → A0 | Pin 3 (GND) → GND

Q4a: Ultrasonic Sensor with Raspberry Pi ★★★ 4/5 Papers [8M]

📌 Working of Ultrasonic Sensor (HC-SR04)

  • Sends 8 pulses of 40KHz ultrasonic sound when TRIG pin is HIGH for 10μs
  • Sound travels to obstacle and returns as echo
  • ECHO pin remains HIGH for time proportional to distance
  • Distance = (Time × Speed of Sound) / 2
  • Speed of sound = 343 m/s = 0.0343 cm/μs

🐍 Python Program — Ultrasonic Distance Measurement on Raspberry Pi

# Ultrasonic Sensor Distance Measurement - Raspberry Pi
# HC-SR04: VCC→5V, GND→GND, TRIG→GPIO23, ECHO→GPIO24

import RPi.GPIO as GPIO
import time

# GPIO Setup
GPIO.setmode(GPIO.BCM)
TRIG = 23
ECHO = 24

GPIO.setup(TRIG, GPIO.OUT)
GPIO.setup(ECHO, GPIO.IN)

def measure_distance():
    # Send 10us trigger pulse
    GPIO.output(TRIG, False)
    time.sleep(0.5)              # Settle time
    GPIO.output(TRIG, True)
    time.sleep(0.00001)          # 10 microseconds
    GPIO.output(TRIG, False)
    
    # Measure echo pulse duration
    pulse_start = time.time()
    while GPIO.input(ECHO) == 0:
        pulse_start = time.time()
    
    pulse_end = time.time()
    while GPIO.input(ECHO) == 1:
        pulse_end = time.time()
    
    pulse_duration = pulse_end - pulse_start
    
    # Distance = (time × speed of sound) / 2
    # Speed of sound = 34300 cm/s
    distance = pulse_duration * 34300 / 2
    return round(distance, 2)

try:
    while True:
        dist = measure_distance()
        print(f"Distance: {dist} cm")
        time.sleep(1)

except KeyboardInterrupt:
    print("Measurement stopped")
    GPIO.cleanup()
⚠️ Important Note: HC-SR04 ECHO pin outputs 5V but Raspberry Pi GPIO can only handle 3.3V. Use a voltage divider (1kΩ + 2kΩ resistors) to protect RPi GPIO.

🐍 Python Program — 4 LEDs Blinking with 5-second delay

# 4 LEDs Blinking with Raspberry Pi
# LEDs connected via 220Ω resistors to GPIO 11,12,13,15

import RPi.GPIO as GPIO
import time

# Setup
GPIO.setmode(GPIO.BOARD)         # Use board pin numbers
GPIO.setwarnings(False)

led_pins = [11, 12, 13, 15]     # GPIO pins for 4 LEDs

# Set all LED pins as OUTPUT
for pin in led_pins:
    GPIO.setup(pin, GPIO.OUT)
    GPIO.output(pin, GPIO.LOW)   # Initially OFF

try:
    while True:
        # Turn ALL LEDs ON
        print("All LEDs ON")
        for pin in led_pins:
            GPIO.output(pin, GPIO.HIGH)
        time.sleep(5)              # Delay 5 seconds
        
        # Turn ALL LEDs OFF
        print("All LEDs OFF")
        for pin in led_pins:
            GPIO.output(pin, GPIO.LOW)
        time.sleep(5)              # Delay 5 seconds

except KeyboardInterrupt:
    print("Program stopped")
    GPIO.cleanup()               # Release all GPIO resources

🧠 Memory Trick: Why is RPi more powerful than Arduino?

RPi = Full Linux OS + Multi-GHz CPU + RAM + WiFi + BT + Multiple USB + Camera. Arduino = Microcontroller (MCU) only, no OS, 16MHz. RPi can run Python, Node.js, databases; Arduino runs only C/C++.

📌 What is Hadoop?

Apache Hadoop is an open-source framework for distributed storage and processing of large datasets using a cluster of commodity hardware. It is based on Google's MapReduce and Google File System (GFS) papers.

🏗️ Hadoop Architecture

🔑 Key Features of Hadoop

FeatureDescription

Cost-EffectiveRuns on commodity (cheap) hardware; open-source framework

✅ Advantages & ❌ Disadvantages

Advantages:
• Processes petabytes of data
• Fault-tolerant by design
• No schema required (schema-on-read)
• Open source — free to use
• Large community support
Disadvantages:
• Not suitable for real-time processing
• Small file problem (HDFS inefficient)
• Java knowledge needed
• No in-memory processing (slow vs Spark)
• Complex cluster management

Bonus: Data Analytics using ThingSpeak ★★ 3/5 Papers [8M]

📌 What is ThingSpeak?

ThingSpeak is an open-source IoT analytics platform service (by MathWorks) that allows aggregation, visualization, and analysis of live data streams in the cloud. It supports MATLAB analytics on IoT data.

⚙️ Steps for Data Collection & Visualization on ThingSpeak

  1. Create Account: Register at thingspeak.com and create a new channel
  2. Configure Channel: Add field names (e.g., Temperature, Humidity), get API key
  3. Connect IoT Device: Program Arduino/RPi to send HTTP GET/POST requests with sensor data

⚙️ Working Process

  7. Slot status updated to Available in real-time

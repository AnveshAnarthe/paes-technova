Unit I — Interaction Foundations
Q1aWIMP Interface Elements[6M]★★★ 5/5
Definition: WIMP stands for Windows, Icons, Menus, Pointers. It is a graphical user interface paradigm that uses these four metaphorical elements to allow users to interact with a computer without memorizing commands.
🔑 The Four WIMP Elements
📋 Detailed Explanation of Each Element
ElementDescriptionExample in MS Word
WindowsRectangular areas showing applications; can be resized, moved, minimized, maximizedDocument editing area, Find dialog box
IconsSmall visual symbols representing files, folders, apps, or actions; clicked to activatePrinter icon, Save icon, Clipboard icon
MenusHierarchical lists of commands; pull-down (from menu bar) or pop-up (right-click)File→Save, Edit→Copy, Format→Font
PointersOn-screen cursor controlled by pointing device; changes shape based on contextArrow for selection, I-beam in text, hand over links
⚖️ Advantages & Disadvantages
✅ Advantages
• Visually intuitive — no command memorization
• WYSIWYG — What You See Is What You Get
• Supports multitasking (multiple windows)
• Easy for beginners — low learning curve
• Consistent UI across applications
• Direct manipulation — drag, drop, resize
• Supports undo/redo operations
❌ Disadvantages
• High memory and processing requirements
• Menu navigation can be slow for experts
• Requires pointing device (mouse)
• Screen can become cluttered
• Difficult to automate repetitive tasks
• Not suitable for visually impaired users
• Limited scripting capability
🧠 Memory Trick

"Windows Icons Menus Pointer" — Think of a Windows OS desktop: you see Windows (apps), Icons (desktop), Menus (taskbar), Pointer (cursor).

Also remember: "WIMP = What I Make Programs"

Q1bExecution-Evaluation Cycle[6M]★★ 2/5
Definition: The Execution-Evaluation Cycle (by Donald Norman) describes how users interact with a system through two phases: Execution (doing something) and Evaluation (checking results). It models the gap between the user's goal and the system's state.
🔑 Norman's Seven Stages of Action
📌 Two Key Concepts — The "Gulfs"
🔵 Gulf of Execution
The gap between what the user wants to do and what actions are available. Poor UI design widens this gulf.
Example: User wants to save but can't find the Save option in menus
🟡 Gulf of Evaluation
The gap between the system's state and how well the user understands it. Unclear feedback widens this gulf.
Example: File saved but no confirmation message shown
🔁 Real-World Example: Saving a Document
  • Goal: Save the document
  • Intention: Use Ctrl+S shortcut
  • Specify: Press Ctrl and S keys together
  • Execute: Press the keys
  • Perceive: Title bar still shows asterisk (*)
  • Interpret: File may not have saved
  • Evaluate: Try File→Save to verify
🧠 Memory Trick

FISE-PIE: Form intention → Intent → Specify → Execute | Perceive → Interpret → Evaluate

Q1cInteraction Styles[6M]★★★ 4/5
Definition: Interaction Styles are the methods through which a user communicates with a computer system. Each style has different characteristics, advantages, and use cases suited to different user groups and tasks.
📋 Five Major Interaction Styles
#StyleDescriptionExample✅ Advantage❌ Disadvantage
1Command Line Interface (CLI) User types text commands; computer processes and responds Linux Terminal, DOS Prompt Fast for experts; automatable with scripts Steep learning curve; must memorize commands
2Menu Selection User selects from a list of displayed options Restaurant POS, ATM screens No memorization; reduces errors Slow for expert users; menu depth issues
3Form Fill-in User fills out structured forms with fields Online registration, Tax forms Familiar mental model; structured data entry Requires keyboard; not for ad-hoc queries
4Direct Manipulation User directly acts on visible objects (drag, drop, resize) Windows Explorer, Adobe Photoshop Intuitive; immediate feedback; undo possible May not scale; hard for screen readers
5Natural Language User interacts using speech or typed natural language Siri, Google Assistant, Chatbots No training needed; accessible Ambiguous input; recognition errors

BonusErgonomics in HCI[6M]★★ 2/5
Definition: Ergonomics (from Greek: ergon = work, nomos = laws) is the scientific study of designing systems and products that fit the physical and cognitive capabilities of the people who use them. In HCI, it focuses on making computer workstations and interfaces comfortable, safe, and efficient.
📌 Disciplines of Ergonomics
#DisciplineFocus AreaHCI Application
1Physical ErgonomicsBody posture, musculoskeletal system, physical workloadKeyboard design, monitor height, mouse grip, chair adjustability
2Cognitive ErgonomicsMental processes: memory, perception, reasoning, attentionUI information architecture, reducing cognitive load, clear navigation
3Organizational ErgonomicsWork systems, job design, teamwork, group dynamicsWorkflow design, collaborative tools, remote work systems
4Environmental ErgonomicsLighting, temperature, noise, vibrationScreen brightness adaptation, noise-cancelling in voice UI
5Visual ErgonomicsVision, eye strain, screen readabilityFont size, contrast ratio, refresh rate, anti-glare screens
⚠️ Common Ergonomic Issues & Solutions
🔴 Problems
• Repetitive Strain Injury (RSI) from typing
• Eye strain (Computer Vision Syndrome)
• Back/neck pain from poor posture
• Carpal tunnel from mouse overuse
✅ Solutions
• Ergonomic keyboards and mice
• Blue light filters, 20-20-20 rule
• Adjustable chairs, standing desks
• Wrist rests and arm supports

Q3aSoftware Design Process Constraints in HCI[9M]★★ 2/5
Definition: The software design process in HCI is shaped by various constraints — limitations and requirements that designers must work within. These constraints define the boundaries within which the design must operate.
📌 Types of Constraints in HCI Design
#Constraint TypeDescriptionExample
1Physical ConstraintsLimitations imposed by hardware, screen size, input devicesMobile screen limits displayed content; touchscreen requires larger tap targets
2Cognitive ConstraintsLimitations of human memory, attention, and processingShort-term memory limited to 7±2 items; menus should not exceed 7 items
3Cultural ConstraintsSocial norms, conventions, and cultural expectationsRed = danger in Western context; different in Asian cultures
4Technical ConstraintsLimitations imposed by programming languages, platforms, APIsWeb app must work on Chrome/Firefox; response time under 2 seconds
5Logical ConstraintsWhat makes sense based on the design's own logic/conventionsGrayed-out Save button when nothing has changed
6Standards & GuidelinesIndustry standards (ISO), platform guidelines (Material Design, HIG)WCAG accessibility standards; Google Material Design guidelines
7Time & BudgetProject constraints on time, money, team sizePrototyping must be completed in 2 weeks; limited testing resources
🔄 HCI Design Process Framework
🔑 Impact of Constraints on Design
  • Norman's constraints classify into physical, logical, semantic, and cultural — each shapes design affordances
  • Trade-offs: More features vs. simpler interface; security vs. convenience
  • ISO 9241 standard defines usability: Effectiveness + Efficiency + Satisfaction within constraints
  • Constraints can be design opportunities — mobile-first forced cleaner, more focused UIs

"PCTLS-TB": Physical, Cognitive, Technical, Logical, Standards, Time, Budget

Q3bPrototyping — Types, Goals & Hill Climbing[8-9M]★★★ 5/5
Definition: A prototype is a preliminary model or mockup of a system/interface created to explore design ideas and test concepts before full development. It allows designers to get user feedback early and cheaply.
🎯 Goals of Prototyping
  • Explore and test design ideas before costly implementation
  • Communicate design concepts to stakeholders and users
  • Gather early user feedback to validate assumptions
  • Identify usability issues early in the design cycle
  • Reduce development risk and rework costs
  • Build shared understanding among team members
📋 Types of Prototyping Techniques
TypeDescriptionFidelityWhen to UseExample
Paper PrototypingHand-drawn sketches of UI on paperLowEarly ideation, quick explorationHand-drawn app screens on sticky notes
WireframingDigital structural layout without colors/fontsLow-MidLayout planning, navigation flowFigma/Balsamiq wireframes
MockupsStatic high-fidelity visual design, no interactionHighVisual approval, stakeholder reviewAdobe XD designs
Interactive PrototypeClickable prototype simulating real behaviorHighUsability testing, user flowsFigma prototype with links
Throwaway PrototypingQuick prototype built only to learn, then discardedLowRequirements clarificationQuick HTML mockup for client demo
Evolutionary PrototypingPrototype gradually refined into final productGrowsAgile/iterative developmentMVP with incremental releases
⛰️ Prototyping with Hill Climbing Approach
Hill Climbing in prototyping is an iterative design strategy inspired by the optimization algorithm. The designer starts with a basic prototype, evaluates it, makes small improvements, evaluates again — always moving "uphill" toward a better design. Each iteration improves the design until an optimal or acceptable solution is reached.
⚖️ Advantages & Limitations of Prototyping
✅ Advantages
• Early detection of design flaws
• Users can give concrete feedback
• Reduces risk of complete redesign
• Bridges communication gap
• Saves development costs
❌ Limitations
• Users may confuse prototype with final product
• Time-consuming for complex systems
• May miss non-visual (performance) aspects
• Hill climbing can get stuck in local optima
• Prototype quality may mislead stakeholders

Q4aUI Layer & Execution Framework[9M]★★★ 4/5
Definition: The UI Layer is the topmost layer of a software system responsible for presenting information to the user and capturing user inputs. The Execution Framework is the underlying runtime environment that manages how UI components are rendered, events are handled, and updates are propagated.
🏗️ UI Layer Architecture
🔑 Components of the Execution Framework
ComponentRoleExample
Event DispatcherRoutes user events (click, keypress) to appropriate handlersJavaScript event queue, Java AWT EventQueue
Rendering EngineDraws UI components on screen, handles repaints/redrawsBrowser DOM rendering, Android View system
Layout ManagerCalculates positions and sizes of UI elementsCSS Flexbox, Android ConstraintLayout
State ManagerMaintains current state of UI; updates when data changesReact useState, Redux store
Input HandlerCaptures and normalizes input from keyboard, mouse, touchTouch event normalization in mobile apps
Thread ManagerSeparates UI thread from background tasks to prevent freezingAndroid AsyncTask, JavaScript Web Workers
🔁 UI Execution Cycle
  • 1. Input Capture: User performs action (click, type, swipe)
  • 2. Event Generation: Input device generates system event
  • 3. Event Dispatch: Framework routes event to target component
  • 4. Event Handler Execution: Application logic processes the event
  • 5. State Update: Application state changes based on logic
  • 6. UI Update: Framework re-renders affected components
  • 7. Display: Updated UI is shown to user
🧠 Memory Trick

"ICE-DAR": Input → Capture → Event → Dispatch → Application → Render

Definition: A scenario in HCI is a narrative story that describes how a user might interact with a system to achieve a goal. Scenarios help designers understand user needs, context, and expected behavior without writing formal specifications.
📋 Types of Scenarios

🎵 Scenario: Music Player Design
Persona: Priya, 22, college student who listens to music while studying.
Goal: Create a playlist and play songs offline.
📖 Task Scenario — Creating a Playlist
Scene: It is 9 PM. Priya opens her music app and wants to create a new playlist for studying.

Step 1: Priya sees the home screen with "Recently Played" and a prominent "+" button for new playlist.
Step 2: She taps "+" and types the name "Study Mix" in the dialog box that appears.
Step 3: The app shows her song library. She searches for "lo-fi" and sees filtered results immediately.
Step 4: She taps the "+" icon next to each song to add it. A counter shows "3 songs added."
Step 5: She taps "Done." The playlist "Study Mix" appears in her library with artwork.
Step 6: She taps the playlist and hits "Play." Music starts immediately.
Step 7: She locks her phone. Music continues in the background with lock screen controls visible.
🔑 Design Decisions from This Scenario
  • Search bar must be always visible (findability)
  • Visual feedback for added songs (progress counter)
  • Background play is a must-have feature
  • Lock screen controls required for usability while phone is locked
  • Offline mode indicated by download icon on songs

BonusMVC Framework in HCI[5-8M]★★★ 3/5
Definition: Model-View-Controller (MVC) is a software architecture pattern that separates an application into three interconnected components. In HCI, it ensures clean separation between data (Model), UI (View), and control logic (Controller).
🏗️ MVC Architecture Diagram
📋 Roles & Responsibilities
ComponentRoleMusic App Example
ModelManages data, business rules, and database interactionsSong metadata (title, artist, album), Playlist data, User preferences
ViewRenders UI from Model data; displays to userSong list screen, Now Playing screen, Album art
ControllerReceives user input, processes it, updates Model or ViewPlay button click → Controller → Model updates state → View refreshes
✅ Why MVC?
Advantages
• Separation of concerns
• Independent development of UI and logic
• Easier testing (Model independently testable)
• Multiple views from one Model
• Maintainable and scalable code
Disadvantages
• Complex for simple applications
• Over-engineering for small projects
• Learning curve for newcomers
• Controller can become bloated (God Controller)

Q5aShneiderman's 8 Golden Rules of Interface Design[9M]★★★ 4/5
Definition: Ben Shneiderman's 8 Golden Rules (1986, "Designing the User Interface") are a set of widely-used principles for designing effective, efficient, and satisfying user interfaces. They apply to virtually all interactive systems.
🏆 The 8 Golden Rules
#Golden RuleDescriptionViolation ExampleGood Example
1 Strive for Consistency Consistent sequences of actions, identical terminology, same commands throughout Ctrl+Z undo in one screen but Alt+Z in another Ctrl+Z always undoes in MS Office
2 Enable Frequent Users to Use Shortcuts Provide abbreviations, function keys, macros for expert users while keeping menus for novices No keyboard shortcuts in a data entry application Ctrl+C/V shortcuts alongside Edit menu options
3 Offer Informative Feedback System should respond to every user action with appropriate feedback File upload with no progress indicator Progress bar + "75% uploaded" message
4 Design Dialogs to Yield Closure Sequences of actions should be organized into groups with a beginning, middle, and end Checkout process that abruptly ends without confirmation "Order Confirmed! Order #12345" page at checkout end
5 Offer Error Prevention and Simple Error Handling Design to prevent errors; if error occurs, detect it and offer simple recovery "ERROR 404" with no explanation or back button Form validates email format before submission
6 Permit Easy Reversal of Actions Actions should be reversible (Undo) to encourage exploration No undo for deleted files; immediate permanent delete Recycle Bin; Gmail "Undo Send" feature
7 Support Internal Locus of Control Users should be initiators of actions, not responders to system actions App randomly shuffles items; auto-save without asking User controls all major actions; preferences for auto-save
8 Reduce Short-Term Memory Load Display information across screens; don't require users to remember info from earlier Shopping cart totals disappear when browsing products Persistent cart icon showing count at all times
🎯 Real-World Application: Gmail
Gmail Golden Rules Analysis
1. Consistent toolbar on all screens ✅
2. Keyboard shortcuts (c=compose, r=reply) ✅
3. "Sending..." then "Message sent. Undo" ✅
4. Email thread shows complete conversation ✅
Gmail Golden Rules Analysis (cont.)
5. Suggests correct email addresses while typing ✅
6. "Undo Send" within 30 seconds ✅
7. User chooses when to send, archive, label ✅
8. Persistent search bar; conversation threading ✅

Q5bGoals of Evaluation & Expert Analysis[8M]★★★ 4/5
Definition: Evaluation in HCI is the process of assessing how well a system meets the needs of its users. It is conducted throughout the design process to find usability problems, compare design alternatives, and ensure the system is fit for purpose.
🎯 Goals of Evaluation
  • Assess extent of system functionality — Does the system do what it needs to?
  • Assess effect of interface on user — Is it stressful, satisfying, engaging?
  • Identify specific problems — Where do users get confused or make errors?
  • Compare alternatives — Which of two designs is better for users?
  • Measure compliance with standards — Does it meet WCAG, ISO 9241?
  • Validate design decisions — Are our design assumptions correct?
🔬 Types of Evaluation
🔍 Evaluation Through Expert Analysis
Expert analysis (also called Analytical Evaluation) uses trained evaluators to assess a system without involving real users. It is cost-effective and can be done early in the design process.
📋 Expert Analysis Methods
MethodProcessOutputBest For
Heuristic Evaluation 3–5 evaluators independently inspect UI against Nielsen's 10 heuristics; results compiled into severity ratings List of usability violations with severity (0–4 scale) Early/mid-stage prototypes; budget-limited projects

🔑 Cognitive Walkthrough — 4 Key Questions
At each step of a task, the evaluator asks:
Q1: Will the user try to achieve the right effect? (Will they know what to do?)
Q2: Will the user notice the correct action is available? (Is the action visible?)
Q3: Will the user associate the correct action with the effect? (Is the label clear?)
Q4: If the action is performed, will the user see it's progressing? (Is feedback given?)

Q7aKeystroke-Level Model (KLM)[9M]★★★ 3/5
Definition: The Keystroke-Level Model (KLM) was proposed by Card, Moran, and Newell (1980) as part of the GOMS framework. It is a predictive model used to estimate the time an expert user takes to complete a task without errors, based on counting low-level physical and mental operations.
⌨️ KLM Operators
OperatorSymbolDescriptionTime (seconds)
KeystrokeKPressing a key or button (including mouse buttons)0.08–1.20 s (avg: 0.28 s)
PointingPMoving the mouse pointer to a target on screen1.10 s
HomingHMoving hand from keyboard to mouse or vice versa0.40 s
DrawingDDrawing lines with mouse (dependent on parameters)Variable
MentalMMental preparation — deciding what to do next1.35 s
Response / SystemRWaiting for system to respondVariable (measured)
🧠 Mental Operator (M) — Detailed
Mental Operator Rules (when to insert M):
• M precedes the first operator in every high-level task action
• M is inserted before K if the K is a command key (not data entry)
• M is not placed before P (pointing) if it immediately follows K
• M is not placed before K that is part of a rapidly-typed string
Key insight: M is the "thinking" time — the pause between deciding to act and acting. Physical operators (K, P, H) are purely physical.
🔑 Physical vs Mental Operators
⚙️ Physical Operators
K, P, H, D — involve physical movement of body parts
• Measured through empirical studies
• Times are consistent across skilled users
• Independent of cognitive processing
Example: K = 0.28s regardless of what key
🧠 Mental Operator (M)
Cognitive preparation time before action
• Accounts for decision making
• Fixed at 1.35 seconds
• Occurs when user must think about next step
Example: M before Ctrl+S = deciding to save
📐 KLM Example — Saving a File with Ctrl+S
Task: User decides to save a file using Ctrl+S (hands already on keyboard)

Sequence: M [KCtrl KS]

Calculation:
• M = 1.35 s (mental preparation — deciding to save)
• K (Ctrl) = 0.08 s
• K (S) = 0.08 s
Total = 1.35 + 0.08 + 0.08 = 1.51 seconds
📐 KLM Example — Opening File via Menu
Task: Open a file using File→Open menu (user starts with hand on keyboard)

Sequence: M H PFile Kclick POpen Kclick

• M = 1.35 s, H = 0.40 s, P = 1.10 s, K = 0.20 s, P = 1.10 s, K = 0.20 s
Total = 1.35 + 0.40 + 1.10 + 0.20 + 1.10 + 0.20 = 4.35 seconds

Comparison shows Ctrl+S is 2.84 seconds faster than menu approach.
✅ Advantages & Limitations of KLM
Advantages
• No user testing needed (saves time/cost)
• Quantitative, objective predictions
• Good for comparing two design alternatives
• Accurate for routine expert tasks
• Simple to apply
Limitations
• Only predicts expert, error-free performance
• Does not model novice users or learning
• Does not account for errors
• Mental operator placement can be subjective
• Not suitable for creative or complex tasks

Q7bLinguistic Model in HCI[9M]★★★ 3/5
Definition: Linguistic models in HCI describe the interaction between user and computer as a form of language exchange. They apply concepts from linguistics (grammar, syntax, semantics) to formalize the structure of user commands and system responses.
🗣️ Why Linguistic Models?
  • Human-computer interaction involves "conversation" — commands and responses
  • Formal grammars can specify precisely what commands are valid
  • Helps detect errors in command sequences automatically
  • Provides a basis for designing and implementing command-line and form-based interfaces
📋 Types of Linguistic Models
#ModelBased OnUse Case
1BNF Grammar (Backus-Naur Form)Formal language grammarsSpecifying command-line syntax
2Syntactic-Semantic ModelParsing theoryUnderstanding typed commands
3TAG (Task Action Grammar)Formal grammarMeasuring learnability and consistency
4CLG (Command Language Grammar)Multi-level grammarAnalyzing multi-level command languages
🔑 BNF (Backus-Naur Form) in HCI
BNF is a notation used to formally specify the grammar of a command language. It defines what combinations of tokens (words, symbols) form valid commands.
BNF Grammar for a simple file command:

<command> ::= <action> <object>
<action> ::= "copy" | "move" | "delete" | "open"
<object> ::= <filename> | <filename> <destination>
<filename> ::= <string> "." <extension>
<extension> ::= "txt" | "pdf" | "jpg" | "docx"

Valid: "copy report.pdf /backup"
Invalid: "report.pdf copy" (wrong order)
🔑 Syntactic-Semantic Model
🔑 TAG (Task Action Grammar)
TAG measures the consistency of a command language by analyzing whether similar tasks have similar command structures.

Principle: If two tasks are conceptually similar, their commands should be grammatically similar (same verb-object structure).

Example: "copy file from A to B" and "move file from A to B" have same structure → consistent design ✅
"copy A B" vs "move-file A B" → inconsistent structure ❌
📋 Comparison — Linguistic vs. Task Models
AspectLinguistic ModelsTask Models (HTA/GOMS)
FocusCommand language structure and grammarUser goals and task decomposition
LevelSyntactic / command levelSemantic / goal level
OutputGrammar specification, consistency metricsTask tree, time prediction
Best ForCLI, form-based interfacesAny interactive system

Q8aHTA — Hierarchical Task Analysis: Cook Rice[9M]★★★ 4/5
Definition: Hierarchical Task Analysis (HTA) is a technique for analyzing tasks by breaking down a high-level goal into sub-goals, operations, and plans. It was developed by Annett and Duncan (1967). HTA provides a structured understanding of what users need to do to achieve a goal.
🔑 Key Concepts in HTA
  • Goal: The end state the user wants to achieve
  • Sub-goal: An intermediate state that contributes to the main goal
  • Operation: A single, indivisible action (the leaf of the tree)
  • Plan: The condition under which sub-goals/operations are executed (sequential, conditional, cyclic)
  • Stopping Rule: Stop decomposing when further analysis won't improve the design
🍚 HTA Diagram: Cook Rice

1Prepare RiceDo 1.1 then 1.2
1.1Measure correct quantity of rice—
1.2Wash rice 2–3 times with clean water—
2Prepare EquipmentDo 2.1 then 2.2
2.1Get pot or pressure cooker—
2.2Add appropriate quantity of water—
3Cook RiceDo 3.1 then 3.2
3.1Place pot on stove or in rice cooker—
3.2Set heat level (high until boiling, then low)—

4.1Check water level and steam—
4.2Reduce heat; wait for absorption—
5Serve and CleanDo 5.1 then 5.2
5.1Turn off stove; let rice rest 5 min—
5.2Serve in bowl; wash pot—
✅ Advantages of HTA
  • Provides clear understanding of user tasks and their structure
  • Identifies opportunities for system support at each sub-goal
  • Helps detect missing functionality in the system design
  • Useful for training material design and error analysis
  • Flexible — can be represented as tree, table, or text

🔑 Model Human Processor (MHP) — Key Details
🔑 GOMS Model
  • Goals: What the user wants to achieve (hierarchical)
  • Operators: Elementary actions user can perform (K, P in KLM)

GOMS Example — Deleting a word:
Goal: Delete word "error"
Method 1: Double-click word → Press Delete key
Method 2: Triple-click to select line → Retype
Selection Rule: Use Method 1 for single words; Method 2 for large sections
